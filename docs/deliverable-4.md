# Deliverable 4 — Final Submission Checklist

This checklist follows the Week 12 final-stage requirements. Human-only evidence remains unchecked until the team performs and records it.

## Repository and application

- [x] Application code is committed in the repository.
- [x] Application has a Railway deployment URL recorded in docs/deployment.md.
- [x] docs/retrospective.md is present.
- [x] Presentation and demo flow is documented in docs/week12-demo-script.md.

## Final live QA

- [ ] Sign in on the deployed application.
- [ ] Create a record and confirm it persists.
- [ ] View a record and confirm stored data is shown.
- [ ] Edit a record and confirm the change persists.
- [ ] Delete a record and confirm the confirmation and removal flow.
- [ ] Submit invalid data and confirm human-readable 422 feedback.
- [ ] Request a missing record and confirm friendly not-found behavior.
- [ ] Verify server and network failure feedback.
- [ ] Verify submit controls remain disabled during pending requests.
- [ ] Verify unusual Unicode and markup is displayed safely.

Record actual results in docs/manual-evidence-record.md.

## Presentation

- [ ] Problem → solution → architecture → live demo → what we learned.
- [ ] Demo uses the deployed application, not localhost.
- [ ] Backup screenshots or short video prepared.
- [ ] Each member has an assigned presentation section.
- [ ] Each member rehearses the exact demo click path.

## Individual defense

- [ ] Each member explains their own code without AI.
- [ ] Each member can explain the invalid-input path.
- [ ] Each member can explain the missing-record path.
- [ ] Each member can identify where validation lives.
- [ ] Each member can name one improvement they would make next time.

## Final evidence rule

Do not claim a manual test, rehearsal, team answer, review, or oral defense occurred until the team has actually completed it and recorded the evidence.
